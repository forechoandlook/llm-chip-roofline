性能建模方法

解析 Roofline，不是 kernel 实测。给定 Qwen3.8-27B 的层结构与 shape，按最少 FLOP / 最少搬运估 Prefill 一次、Decode 一步的下限。芯片只提供 Cube / Vector / HBM 峰值；HBM 容量只做工作集是否装得下，不进时间公式。

1. 体积

NVFP4 / MXFP8 / W4BF16 的 MatMul 公式在页面最上方的表里。下面是其余算子。

  • FlashAttention 始终 BF16 Cube：4·causal·B·Qh·S·C·D（QKᵀ+PV）。online softmax（running max / exp / 归一化）+ O 按块缩放走 FP32 Vector。head_dim=256 时 Cube:Vector FLOP 大约 26:1；B300 上 TV 已和 TC 同一量级。
  • GDN delta rule：Cube BF16 6·M·Vh·D²，Vector FP32 2·M·Vh·D²（状态衰减，无 FP32 Cube）。FP32 峰值跟 Vector 一起按 Cube:Vector 缩放。
  • RMS / SiLU / 残差 / RoPE：纯 Vector。强度大约 3 FLOP/byte，通常先碰到搬运。

2. 单算子时间

TCube = FLOPCube / Cube峰值
TVector = FLOPVector / Vector峰值
T带宽 = Bytes / HBM GB/s
T算力 = max(C, V) + [γ + (1−γ)/ntiles] · min(C, V)
T = max(T算力, T带宽) + α · min(T算力, T带宽)

  • GEMM tile 约 128×128：同一 tile 上 Vector 等 Cube 写出；tile 之间 Cube∥Vector。稳态 ≈ max(C,V)，头尾气泡 min/nTiles。
  • γ（左侧「Cube∥Vector γ」）是即使很多 tile 也藏不住的串行份额。0 = 完全并行，1 且 tile 少 ≈ C+V。默认 0.4。
  • α 是算力与 HBM 的不完全重叠。默认 0.2。FlashAttention α=0（视为融合、算力与 KV 搬运不同时计双份）。
  • RMS / SiLU / 残差 / RoPE 的 HBM 按「Epilogue 计 HBM」比例计入（默认 0.2，当片上为主）。GEMM、FA、权重仍按全量 HBM。

3. 端到端与墙

  • Prefill / Decode 总时间 = 各算子 T 相加（算子之间不重叠）。
  • Decode tok/s = Bd / 一步时间。Prefill tok/s = Bp·seq / Prefill 时间。
  • 墙：三条时间里高出另外两条约 15% 的那条（Cube / Vector / 带宽）。流水 T 里还含 γ、α，标签和 T 可能差一档。
  • Prefill 默认四条独立 8K，不是一条 32K：FFN 的 M=Bp·seq，FA 仍按每条序列的 S。

4. 扫配比

  • 折线和热力图都 固定当前 Cube BF16。拧 Cube:Vector 只改 Vector（以及跟 Vector 走的 FP32）。拧带宽:Cube 只改 HBM = 比值 × Cube TFLOPS。
  • 这是「会不会拖 Cube / 会不会拖 Decode」，不是等面积最优。没有功耗、SRAM 驻留、五段 tile 流水（那些在 chip-simulator）。

扫 Cube : Vector

固定当前 Cube BF16 峰值，只改 Vector（FP8/FP4 随 Cube 不变，FP32 Vector 跟 Vector 同比缩放）。8:1～16:1 附近 Prefill 仍多半是 GEMM Cube。再往瘦（32:1、64:1）线会翘，因为 GDN 衰减是 FP32 Vector（没有 FP32 Cube），FlashAttention 的 online softmax（动态 max / exp / 归一化）也走 FP32 Vector；这两项时间随 Vector 峰值线性变长，会盖过已经固定的 Cube。

扫 带宽 : Cube

固定 Cube 和 Vector，只改 HBM。Decode 通常随带宽上升；Prefill 在算力墙时这条线会变平。

关键算子 · 扫 Cube : Vector

三条都是 Prefill 全层合计。FFN MatMul 含 gate/up/down 和量化。FlashAttention 是 16 层。GDN 线性注意力是 48 层 delta rule（BF16 Cube + FP32 衰减），不含投影 GEMM。Cube 固定、只拧 Vector：MatMul 几乎水平；Attention 和 GDN 衰减走 FP32 Vector，变瘦后会翘。

Decode 热力图 · Cube:Vector × 带宽:Cube

  • 看什么：每个格子是 Decode tok/s（数字越大越好）。颜色偏青快、偏橙红慢。橙框是当前配比（落在最近格子上）。
  • 横轴 带宽:Cube，往右 HBM 更宽，搬权重更快。
  • 纵轴 Cube:Vector，往上 Vector 更瘦（8:1 → 16:1 → 64:1）。Cube BF16 全程固定。
  • 悬停 看这一格的墙（带宽 / Vector / Cube）和每步毫秒。
  • 同一列往上：HBM 不变、Vector 变瘦。数字几乎不变 → 还在搬权重；数字掉下去 → Vector 已经盖过搬运。
  • 同一行往右：Vector 不变、HBM 变宽。数字涨 → 缺带宽；数字不动 → 已经卡在 Vector（或 Cube）。
  • 怎么决策：橙框所在列整列同色同数字 → 先加 HBM。橙框往上开始变红 → 不要再砍 Vector（W4 是反量化 3KN；NVFP4 的 s_global 乘是 MN，Decode 先碰到的是带宽）。
  • 精度：MXFP8/FP8 多半整张都是带宽墙，横着走才涨。Decode 很少出现 Cube 墙（batch=4 投影强度不够）。
